# Design documents

Each document explains one decision that is still in force: the context, the decision, why, the alternatives, the
consequences, where it is in the code, and links to the log entries. The decision logs
([../decisions/](../decisions/README.md)) are the archive.

Engine, rules, fork and protocol decisions are in the engine repository's design documents
([`docs/design/`](https://github.com/abstractclass-org/engines/blob/main/docs/design/README.md) and
[`games/enclosure/docs/design/`](https://github.com/abstractclass-org/engines/blob/main/games/enclosure/docs/design/README.md)).
This folder holds product decisions.

| 16 | [How deep a review searches, which result a position uses, and whose settings apply](16-depths-and-settings.md) | Every depth a review asks for, in one table: the sweep, the depth per move, the Greats' equal searches, and the position on screen. | 18 | [Links from other sites, and reviews saved back](18-partner-links.md) | A site where Enclosure is played links a finished game to `/import#record=…` (design 22): the game is kept in the browser and its review opens, with a link back to the game's page from its `Site` tag. Other variants are refused. A partner's link names its save page: the Export menu's "Save to …" sends the review file there by window messages, when the player asks, and the partner's page sends it back the same way to open it again. The link and the handshake are described on the /developers page, with what can change. |

| 20 | [A review by an earlier engine opens as it was](20-snapshot.md) | After a release, a game reviewed before opens as a snapshot of that review, from the stored results: no search, no new moves, no export, and Review again. | 21 | [The Analysis board](21-analysis.md) | A free board beside the review: the standard start or a line brought in, the engine on the position on screen only, the player's main line (Make main line), labels only on request, one board kept in each browser, shared by a link or as a record. The board editor and starts from another position wait for the engine's check of a position (request 16). |
| 22 | [The site's pages and their addresses](22-site-map.md) | Each page takes its own way in after the `#`: `/review#packed=`, `#from=`, and `/analysis#record=`, `#packed=`, `&at=`. Parameters are named by their payload's format. `/import` takes every game from outside for the review: a tool's game asks where it goes, and a link's `record=` is kept and reviewed at once. The meaf.us tools' page is `/tools`. The analytics start once a page has taken a game out of its address. |
| 23 | [Search engines and link previews](23-search.md) | The live address is indexed, Cloudflare's preview addresses are not. Each page has its title, description, canonical address and Open Graph tags, with one preview image. A sitemap, structured data on Home, and the site registered in Google Search Console. |
| 24 | [Practice: a game against HedgeFund in the browser](24-practice.md) | `/practice`: a game against the engine's practice bot in the player's browser, with no server and no clock. The network, the visits and the variety, fixed for a game. Blue, Red or Random. No evaluation. Take back by turn, Abort at any time, Resign, and steps back through the positions. The review's row, move list, bar and display settings. One game in progress, kept. Games go into Your games, named by both sides. |
| 25 | [Practice games, stored for the bot's levels](25-practice-games-stored.md) | Every practice game stored when it ends, on a Cloudflare Pages Function and D1, as Lichess keeps every game: its moves, the bot, the outcome, the takebacks and the times, never a name or an IP address. A random number per browser with the visitor's consent, and a choice for each purpose. May be published as an open dataset. Built: it stores games once the databases are set up. |
| 26 | [One repository for the learning sites](26-one-repository.md) | Hedge School moves whole into `apps/hedgeschool`, beside a hub at `abstractclass.org` (a page of links, no analytics). Built: the move, in one npm workspace. Its check on a preview deploy, and the hub, are still to do. |
| 27 | [A request to the visitors whose blocker stops Google Analytics](27-analytics-ask.md) | A visitor who accepted Google Analytics, and whose Google tag did not run, is asked to allow the site in the blocker until they close the request: in the consent banner's card and place, after the banner. The page checks its own tag, not blockers. Never a visitor who declined, never a wall, and no proxy past blockers. No event: it could not arrive. |
| 28 | [The lessons on the engine's rules](28-lessons.md) | Each step's board is a teaching board, a line of the notation that the engine reads, with its check ignored. The engine gives the input the legal edges, plays the edge and draws the board after it. Each step keeps a test of its task only, on the engine's boards. A legal edge that fails the task is not placed: the hint shows and the board stays. |
| 29 | [The shared packages](29-shared-packages.md) | The engine, the storage and the analysis (the review's model and labels, the move tree, the cache, the passes, the session) in `packages/`, for a jam game's site beside Hedge School. A game interface carries the game's own: a move's name, a position from the engine, a move played, the rules for the player's moves, a line's steps and the turn numbers. Generic types, with Hedge School's field names kept. The views wait for the jam site's template. |
| 30 | [The area map](30-area-maps.md) | Every search stores the ownership of each point. Three styles, each named by what it compares: Forecast (KaTrain's Territory, the default), Forecast vs board (what is still to happen), and After vs before (what the last move or the drawn line changed: KaTrain's loss grid at every move, with the rises). The player sets the smallest value marked. The map is always the map of the position that the board shows, and follows a line as it is drawn. A position's missing map comes from a short search, stored on demand, and a pass makes an older review's maps. Off on the review, on on the Analysis board, a switch above the board, the keys t and Shift+T. |
| 31 | [The threat](31-threat.md) | Lichess's "Show threat": a switch in the engine header and the key x. The engine searches the position after a pass by the side to move, as the position on screen is searched, below it. The header gives the values after the pass and what the pass costs, in a move's loss units. The board draws the opponent's turn from there as a line, its numbers in warning triangles, and the area map follows it. Stored and read as the other results. A snapshot reads it from the store alone. |
| 32 | [The opening book explorer](32-book-explorer.md) | For people to learn: after a game and study first. Openings (`/openings`), a page with the Analysis board's layout, and the book's table in the candidates' place on the review and the Analysis board, with a "Book" and "Candidates" switch. Groups: fine moves, other book moves, traps with both values and their refutation, the best move outside the book, the game's move. One sentence a turn from the book's facts. The review's Report names where the game left the book. Built: the book file's form, its loader and a test book. The explorer is not built. |
| 33 | [Drawing Board: Blueprints' site](33-drawing-board.md) | Drawing Board, at `drawingboard.abstractclass.org`, with Stamp Duty as its engine and bot. Hedge School's pages, layout, review and settings, with only the game's parts changed. No rehearsal game: the view's split happens on Blueprints' board. Shared parts move into `packages/`. strategyjam.org's moves as they are (`K@q,r`, `I:q,r>J:q,r`, an edit's coordinates read before the edit), with `x` and `x+N`, and Hedge School's record by turn. Two edits can give one hand, so the review compares positions. The engine's browser build is request 23. |
